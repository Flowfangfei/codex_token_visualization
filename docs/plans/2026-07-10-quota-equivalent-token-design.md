# 额度等效 Token 与重置分段设计

## 目标

预测 Codex、Claude Code 和 Cursor 的账户额度耗尽时间，同时处理模型消耗差异、自动周期和同一天内的手动额度重置。

## 统计口径

不使用 API 价格直接换算订阅额度。API 账单价格与订阅产品的内部限额扣减不是同一口径，固定价格权重会制造虚假的精度。

预测采用分层降级：

1. 全部历史少于 2 个有效消耗区间时，只显示官方剩余额度和原始 Token 速率。
2. 达到 2 个有效区间且近期模型覆盖、组合稳定性检查通过后，以跨重置周期汇总的 Token 增量对官方已用百分比增量做过原点最小二乘拟合。
3. 达到至少 7 个跨周期有效区间、存在至少两个主要模型且模型占比变化足够时，以单变量斜率为先验，用岭回归学习模型相对权重。
4. 2026-09-05 修订：跨周期模型权重不再限制在任意的 `0.25x` 到 `4x`；改为正系数、每个近期主要模型至少 3 个有效区间、近期扣减偏差与整体质量检查。只有组合稳定时允许原始 Token 回退，否则暂停定量预测。具体门槛与局限见 README“新模型与等效 Token 的含义”。旧日累计拟合入口仅为兼容保留，不能绕过近期区间校准检查。

每个重置周期拥有独立起点，只提取周期内部相邻观测之间的增量。这等价于给各周期设置独立固定效应，既隔离重置跳变，又允许旧周期继续贡献斜率信息。有效区间使用 28 天半衰期的指数时间权重，并使用 Huber 型稳健权重降低异常区间影响。

模型校正后的内部单位称为“模型等效 Token”。它只用于当前账户和保留期内观测数据的预测，不表示官方公开换算率，也不跨产品复用权重。

## 日内重置

每日 token JSON 和每日额度快照仍按日期覆盖。额外的观测文件记录每次有效刷新时的：

- 长周期窗口名称、已用百分比和重置时间；
- 当前累计 Token；
- 当前累计的分模型 Token；
- 分段编号和重置检测原因。

以下任一条件会开启新分段：

- 重置时间变化超过 5 分钟；
- 已用百分比下降超过 0.5 个百分点；
- 本地累计 Token 计数回退。

重置时间允许 5 分钟容差，用于吸收 Claude 等接口的毫秒级时间抖动。拟合不会使用跨分段的 Token 增量，所以同一天重置前后的用量不会混合；但重置前各分段内部形成的有效区间仍会保留并参与后续拟合。当前分段只决定当前已用额度、剩余额度和重置时间，不会清空历史学习结果。

同一天允许连续建立任意多个分段。前端优先尊重采集端写入的分段编号，并继续用重置时间、额度单调性和累计 Token 单调性做防御性校验。单日超过 96 条观测时，压缩过程优先保留每次重置前后的边界点及各段首尾点，再补入最近的普通观测。

系统只能分辨同步点之间可观察到的状态变化。如果多次重置全部发生在两次同步之间，且最终快照没有额度回落、重置时间变化或累计计数回退，则无法可靠推断中间发生过多少次重置。手动重置后应触发一次全局刷新，为新分段留下锚点。

## 存储与安全

观测按来源、按天保存，每个文件最多 96 条，保留 120 天。相同额度和 Token 状态会去重。文件不保存 access token、refresh token、cookie、原始事件、会话内容、邮箱或账户 ID。

浏览器“全部刷新”和 Windows 每日 12:00 计划任务均执行同一流程：导出三个本地用量源、同步三个账户额度源、写入去重观测点，然后重新加载页面。
