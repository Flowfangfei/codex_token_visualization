# 额度等效 Token 与重置分段设计

## 目标

预测 Codex、Claude Code 和 Cursor 的账户额度耗尽时间，同时处理模型消耗差异、自动周期和同一天内的手动额度重置。

## 统计口径

不使用 API 价格直接换算订阅额度。API 账单价格与订阅产品的内部限额扣减不是同一口径，固定价格权重会制造虚假的精度。

预测采用分层降级：

1. 少于 3 个当前分段观测点时，只显示官方剩余额度和原始 Token 速率。
2. 达到 3 个观测点后，以 Token 增量对官方已用百分比做单变量最小二乘拟合。
3. 达到至少 7 个观测点、存在至少两个主要模型且模型占比变化足够时，以单变量斜率为先验，用岭回归学习模型相对权重。
4. 模型权重限制在基准的 `0.25x` 到 `4x`；加权拟合质量下降、样本不足或模型混合不可辨识时，自动回退到原始 Token。

模型校正后的内部单位称为“模型等效 Token”。它只用于当前账户和当前观测数据的预测，不表示官方公开换算率，也不跨产品复用权重。

## 日内重置

每日 token JSON 和每日额度快照仍按日期覆盖。额外的观测文件记录每次有效刷新时的：

- 长周期窗口名称、已用百分比和重置时间；
- 当前累计 Token；
- 当前累计的分模型 Token；
- 分段编号和重置检测原因。

以下任一条件会开启新分段：

- 重置时间变化超过 5 分钟；
- 已用百分比下降超过 0.5 个百分点；
- 本地累计 Token 计数回退。

重置时间允许 5 分钟容差，用于吸收 Claude 等接口的毫秒级时间抖动。拟合只使用当前连续分段内的 Token 增量，所以同一天重置前后的用量不会混合。

## 存储与安全

观测按来源、按天保存，每个文件最多 96 条，保留 120 天。相同额度和 Token 状态会去重。文件不保存 access token、refresh token、cookie、原始事件、会话内容、邮箱或账户 ID。

浏览器“全部刷新”和 Windows 每日 12:00 计划任务均执行同一流程：导出三个本地用量源、同步三个账户额度源、写入去重观测点，然后重新加载页面。
