# Banked reset：最优控制模型与验证

## 结论先行

可以对一个明确、可检验的模型求最优，但要区分三件事：

1. **解析特例**：需求足够低、自然恢复已能满足所有需求时，不重置达到需求上界，连续时间下也是全局最优。单次重置、期间没有自然恢复时，可用有限个折点给出解析解。
2. **确定性规划**：对给定需求曲线、周期规则、有限规划期和重置时刻网格，用动态规划求网格全局最优，不再使用 beam search 截断状态。
3. **未知未来**：不能证明现实中必然获得最大收益。随机动态规划需要需求的条件分布；当前实现做历史分块压力检验和刷新后的滚动重算，不把它冒充已经标定好的随机最优策略。

本次还加入“今天优先续工”：先最大化未来 24 小时可支持量，再最大化全期可支持量。它与“全期最多可用额度”是不同的目标，不应偷偷混用。两者均以当前账户窗口的额度百分点计量，不以原始 Token 数量衡量收益。

## 相关模型

- **随机库存控制**：余额相当于库存，reset 是有到期日的补满权利，自然恢复是定时且不可累积的补货。Levi、Janakiraman、Nagarajan 讨论随机需求、缺货和动态规划，也区分即时丢失的需求与可以积压的需求。这里借用建模思想，不继承其 2-近似定理，因为本项目的补满和周期重启机制不同。[作者论文](https://www.mit.edu/~retsef/publications/refjour/lostsales.pdf)
- **多次最优停止 / swing option**：多张有时限的行权权利，在不同时间行权会改变后续价值。Carmona 与 Touzi 研究多次行权；其特殊永久期模型有构造解，有限期使用数值方法。Banked reset 类似使用权，不是可交易证券，也不采用 Black–Scholes 假设。[作者论文](https://carmona.princeton.edu/sites/g/files/toruqf5466/files/documents/swing1.pdf)
- **滚动时域控制 / MPC**：每次观测后重新优化，只把近期行动作为当前建议，远期时间表是条件性的。适合需求和模型组合变化，不要求一次锁定整月日期。[Wang、Boyd 等的 RHC 说明](https://www.web.stanford.edu/~boyd/papers/code_gen_rhc.html)

以上是建模对应关系，不是说文献已经直接解决了 Codex 或 Grok 的具体额度规则。

## 确定性模型

取每个完整额度池容量为 `Q = 100`，不直接假定一个池等于固定数量的原始 Token。

| 记号 | 含义 |
| --- | --- |
| `b` | 当前可用额度百分点 |
| `r0` | 下一次自然恢复时刻 |
| `P` | 一个窗口的时长 |
| `e_i` | 第 i 张 reset 到期时刻，升序排列 |
| `D(t)` | 从现在至 t 的累计需求，以额度百分点计 |
| `H` | 最后已知到期后一个周期，最多未来 60 天 |
| `U` | `min(H, 24 小时)`，续工优先目标的截止时刻 |

现有页面用已校准的额度消耗速率，默认 `D(t)=lambda*t`；计算模块也能处理分段常数需求率。模型权重在既有校准层处理：`E = sum(w_m*T_m)`，拟合 `deltaQuota = beta * deltaE`，再估计 `lambda = beta * dailyEquivalentTokens`。权重和 beta 从同一窗口的有效增量学习，不使用 API 价格倍率。

原始与等效 Token 辅助折算分别是 `gainPercent * rawDailyTokens/lambda` 与 `gainPercent * equivalentDailyTokens/lambda`；未启用模型权重时等效字段为 null，不以原始 Token 补位。求解器、规则情景比较、续工、压力检验、更多待办及证书均保留额度百分点。改变 Token 基准但保持 lambda 不变不会改变计划，这是回归测试覆盖的不变量。

新主要模型不自动继承“其他模型”权重；原有跨周期岭回归的 `0.25–4` 硬截断已移除，改为正系数检查、每模型样本覆盖、近期实际扣减偏差检查和整体拟合质量检查。等效 Token 仍是本次拟合的相对刻度，不是跨模型版本、跨套餐稳定的货币。校准门槛及局限见 README 的“新模型与等效 Token 的含义”。不能区分的模型组合暂停定量规划，历史区间仍保留。

一个恢复段内，若起点余额为 q，段内需求为 d，则实际支持量为 `min(q,d)`。自然恢复及 reset 都是补满而非相加，原有未用余额会被丢弃。

`restart`：在 s 使用 reset 后，下一次自然恢复为 `s+P`。

`fixed`：在 s 使用 reset 不改变原自然恢复日历。

Grok 规则尚未确认时分别求解以上两个条件模型，不声称主表是同时适用于两种规则的 maximin 策略。

### 目标和业务含义

全期目标是最大化及时支持的总需求：

\[
\max_\pi J_H(\pi) = \int_0^H \text{served}_\pi(t)\,dt.
\]

收益报告为 `J_H(计划) - J_H(不重置)`，比较相同需求、相同时间范围。它不是现金收益，也不是实际工作价值。

当前模型将当时未满足的需求记为未及时支持，不自动积压为以后无限赶工的待办。如果任务可以延期、每项价值不同或有截止日，需另外提供队列、价值和截止约束；本地 Token 汇总不能识别这些信息。

尤其要注意**需求被限流截断**：日志记录的是已经完成的消耗，而不是本来想做却没有额度的工作。不能将额度耗尽后的低 Token 日解释为用户没有需求。当前没有足够任务到达信息来无偏恢复潜在需求，所以“今天优先续工”和额外待办情景保留为明确的条件方案。

“今天优先续工”采用词典序目标 `(J_U, J_H, -reset次数, -丢弃余额)`。先最大化 `J_U`，只有近期收益相同时才比较 `J_H`。全期目标使用 `(J_H, -reset次数, -丢弃余额)`。这避免凭空给“今天价值”设一个货币权重。

## 一个可用的解析特例

若需求率恒定为 `lambda`，`lambda*P <= Q`，且当前余额足以覆盖下一次自然恢复前的需求，则所有需求都能被满足：

\[
J_H^*=D(H)=\lambda H,\quad \pi^*=\text{不重置}.
\]

因为任何策略都不能支持超过总需求的工作，此时不是“搜索没找到更好”，而是达到了可证明的上界。代码进一步直接检验不重置的实际支持量是否等于总需求，覆盖有限期下更多类似情况。

另一个特例：只有一张 reset、规划期内没有自然恢复、恒定需求，使用时刻 `s` 的支持量为：

\[
f(s)=\min(b,\lambda s)+\min(Q,\lambda(H-s)),\quad 0\le s\le e.
\]

`f` 是分段线性的。最大值只需比较端点 `0,e` 和截断到可行区间内的折点 `b/lambda`、`H-Q/lambda`，再与不重置比较。多张到期权利和周期重启会引入更多互相耦合的折点；这里没有宣称找到一般连续时间闭式公式。

## 动态规划为何可以精确压缩

每次完整 reset 后，余额固定为 Q；在已知周期规则下，下一次恢复日由最后 reset 时刻 s 唯一决定。因此，固定最后 reset 时刻后，更早的历史只通过已经获得的收益和已处理的权利数影响未来。

令 `G(s,t)` 表示在 s 完整重置、到 t 前不再手动重置时的支持量，期间自然恢复全部照常计算；`G0(t)` 表示从当前真实状态起，不手动重置至 t 的支持量。

设 `F_i(t)` 为只考虑前 i 张权利、最后一次完整重置位于网格时刻 t 的最优已支持量。可以跳过第 i 张，也可以在 t 使用它：

\[
F_i(t)=\max\left\{F_{i-1}(t),\ G_0(t),\ \max_{s<t}[F_{i-1}(s)+G(s,t)]\right\}.
\]

后两项只有在第 i 张仍可用、余额非满且满足对应丢弃余额限制时才允许。最终比较：

\[
J_H^*=\max\left\{G_0(H),\ \max_t[F_K(t)+G(t,H)]\right\}.
\]

强制用完库存时，删除“跳过”项，`G0(t)` 只允许用于第一张；无可行路径就明确报告不可行。续工优先时把边权扩展为 `(截至U的支持量, 全期支持量)`，保持同一个递推结构。

### 最优性证明要点

1. 所有权利目前已可用、作用相同，仅到期时间不同。若先用较晚到期权利，再用较早到期权利，交换两者不改变物理状态，且不破坏可行性。因此可以按最早到期顺序处理，并允许跳过。
2. 任意合法网格时间表，要么不手动重置，要么有最后一次重置 t；重置前有最后一次 s，或根本没有前次重置。
3. 这恰好是递推枚举的全部情形。相同 `(i,t)` 的两个历史具有相同未来状态，可以安全丢弃收益较差者，不需要按余额桶近似合并。
4. 对 i 归纳得到每个状态的最优性，最后比较终点收益得到网格全局最优。

实现使用 IEEE-754 双精度和 `1e-7` 额度百分点的比较容差。不存在 beam 宽度或按余额四舍五入剪枝。

复杂度为 `O(K*N^2)`，N 是允许的重置时刻数量；保存每层和回溯路径。默认半小时网格，额外加入到期前 1 小时、原自然恢复时刻、24 小时截止和确定性需求变化边界。库存较多时按计算预算加粗网格，页面明确显示真实步长和点数。

**最优性只针对所显示网格、已纳入库存及已声明的周期/需求假设。** 到期前 1 小时是操作余量，而不是官方提前失效。未来 60 天和最多 24 张的限制仍然存在。

## 连续时间上界与证书

任意策略不能支持超过总需求。放松余额丢弃、到期和需求时序约束，允许把全部可能恢复的额度完美利用，还得到供应上界：

\[
UB=\min\{D(H),\ b+Q(K+N_{\mathrm{natural}}^{\max})\}.
\]

固定日历使用规划期内实际自然恢复次数。重启日历的自然恢复之间至少间隔 P，因此可以取 `ceil(H/P)` 作为上界。规划终点时刚补满但尚未消耗不算已支持量。

页面显示 `UB-J_H(安排)`。差为零，证明在此确定性模型内达到了连续时间全局最优；差非零时，它只是一个可能较松的最优性差距上界，不能据此声称存在这么多可实现的提升。它也不是需求预测误差或统计置信区间。

## 波动、经济学模型与还没做到的部分

更一般的状态可以写成 `x=(余额, 下次恢复日, 剩余权利, 负载状态z)`。随机 Bellman 方程为：

\[
V_t(x)=\max_{a\in A(x)}\mathbb E[\text{served}_t(x,a,D_t)+V_{t+1}(T(x,a,D_t))\mid\mathcal F_t].
\]

`F_t` 只能包含当时已知信息。长期工作强度可以考虑 Markov regime，短期扰动可以考虑条件 AR 模型、块自助法或场景树；但需要足够长、同口径的历史，以及样本外检验。当前没有用 28 个日总量强行拟合长期振荡，也没有假定需求服从金融价格过程。

当前落地的是可审计的较保守版本：

- 使用最近最多 28 个完整日；剔除今天未完成日，历史起点后的无日志日按现有账本口径视为零。输入不足 14 日或不足 4 个非零日时不做波动结论。
- 以连续 3 日为块重采样，保留局部高低负载持续性，用固定种子生成 8 条压力路径。
- 4 条均匀分摊到日内，另外 4 条假设集中 6 小时工作；后者是人为压力条件，不是实际作息识别。
- 对同一固定时间表计算增益、未及时满足需求和负收益案例；不会为每条未来路径重新寻找最优时间表后称其为“可获得收益”。
- 额外比较“当前有工作且额度用尽才使用最早到期 reset”的响应策略。此策略只使用当前余额、当前需求及已知有效期，不看未来负载；它有时比固定时间表更差，也会明确显示。
- 每次全局刷新后，使用新观测重新校准并规划。这里只有建议，不执行兑换。

压力案例均值不是期望收益的可信估计，8 条路径的负收益比例也不是现实概率。这里尚未实现严格的随机 DP、CVaR 最优策略、价值加权任务队列，或稳定性有保证的自动控制器。

## 可重复验证

```bash
npm test
node scripts/benchmark-reset-planners.cjs
```

穷举对照覆盖固定/重启周期、突发需求、空/满余额、丢弃限制、同日多次重置、两种目标及提前到期。测试使用独立事件模拟器，而非复用动态规划的收益公式作为答案。

固定种子的 100 组**合成**案例，在相同半小时网格上比较旧 beam 与新 DP：43 组严格改善，0 组退步。差异最大案例的支持量由 `575.708333` 提高到 `731` 额度百分点，增加约 `155.291667` 点。每 100 点代表一个归一化完整池，不是一个真实账户的收益承诺。

该案例当前余额 31%，22 小时后自然恢复，需求每天 58 个百分点，周期 7 天，规划 24 天；4 张权利分别在第 91、190、190、284 小时到期。DP 保留了提前连续补满的路径，旧 beam 的候选截断丢失了它。这个反例已单独固化为回归测试。

若账户当前的低需求已全部被自然恢复满足，新旧算法都应给出零额外增益，不能为了展示改进而制造收益。
